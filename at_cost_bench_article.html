What test-first ceremony costs when the implementer is an LLM agent

We gave the same specifications to an LLM coding agent twice: once under branch-grained red→green discipline, once with no ceremony at all. Both had to clear the same bar — full line coverage and mutation testing. Across eight measured runs, skipping the ceremony cost about one eighteenth of the tokens and reached tests of the same strength.

The question

Test-driven development is usually argued about with opinions. The red→green→refactor loop is defended as a design discipline and attacked as overhead, and both sides mostly speak from experience with human programmers. When the implementer is an LLM coding agent, the question becomes concrete and measurable: every red test, every green run and every round-trip is a billed request. So we asked a narrow question — if two ways of working must clear exactly the same verification bar, what does the test-first ceremony itself cost?

How the bench works

Each run takes one task specification and gives it to two arms:

  • RGR (branch-grained). Textbook red→green discipline enforced by protocol: one failing test per design decision, one [Fact] per cycle, and the red must be a real failure against the current implementation.
  • Direct-to-GREEN. The agent writes the implementation and its tests together; incidental failures are repaired.

The obligations are equalized: both arms are held to full line coverage and are scored by mutation testing (Stryker) on the same task. Every run records its full turn ledger — tokens, wall-clock time, each test run classified as a planned red, an accidental red, a green, or a vacuous red (a test written to fail that passed anyway), oracle-adjudication turns, coverage, mutation scores and per-member outcomes.

Cost is measured in effective tokens: output + input + 0.1 × cached reads. All eight runs used the same model (claude-sonnet-4-6) and the same harness (COST_BENCH v2). The RGR arm was deliberately run under a favorable variant of the discipline: the "nano-cycle" component — stop writing at the smallest failing fragment, counting a compile error as a failure — was removed, so each cycle can write one whole test.

The direction never flips. In every one of the eight runs, Direct-to-GREEN finished with a small fraction of the tokens and the time. The smallest gap was ×10.8; the largest was ×26.3. The largest absolute cost, SEQ 23, is also the largest task: RGR needed 127 round-trips and almost sixteen minutes, Direct needed two round-trips and about two minutes.

Where the RGR tokens go

Direct-to-GREEN finished seven of the eight runs in a single round-trip and the eighth in two — nine in total, against 386 for RGR. The difference is the ceremony itself: RGR made 370 test runs, Direct made 10.

Many of those 370 runs did not do what the discipline expects of them. 141 of them (38%) were vacuous reds: a test written to fail that passed the first time it ran, so the "red" step proved nothing. Another 26 were accidental reds. Only 93 were the planned reds the protocol is built around.

The cost of test-first is not mainly writing tests — both arms wrote plenty of test code. It is the loop: one request per red, one per green, and a large share of reds that never actually fail.

Did the ceremony buy stronger tests?

Not in these runs. Coverage reached 100% in both arms in six of the eight runs; the two exceptions differ by 2.4 points (SEQ 21: 94.7% vs 92.3%) and 0.7 points (SEQ 23: 99.3% vs 100%), one in each direction. Mutation scores stay within five points of each other in every run. RGR scored higher in four runs, Direct in two, and the two arms tied in two. Neither arm is consistently stronger, and the differences are far smaller than the tenfold-plus difference in cost.

What this does and does not show

  • It measures the cost of the red→green loop when the implementer is an LLM agent and the verification bar is fixed in advance. It says nothing about TDD as a thinking tool for human programmers.
  • The sample is small: eight runs, one model, small C# business-logic tasks, with specifications written in Japanese.
  • The RGR arm ran under a variant that is already favorable to it (no nano-cycle). A stricter reading of the discipline would add cycles, not remove them.
  • The quality bar here is coverage plus mutation score. Other properties — design, readability, how the code ages — are not measured.

The point

When an LLM agent writes the code, the red→green loop is paid for one request at a time, and in these runs it did not buy better tests. Holding both arms to the same coverage and mutation bar, going straight to green reached that bar with about one eighteenth of the tokens and a seventh of the time. If the budget is fixed, it is better spent on the verification itself — coverage, mutation testing and a trustworthy oracle — than on the ceremony.
